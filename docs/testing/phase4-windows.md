# Phase 4 Windows 테스트: 메인 창 ↔ 사이드바

Phase 1 체크리스트(`phase1-windows.md`)와 함께 확인한다.

## A. 첫 실행
- [ ] 실행하면 메인 창(약 1400×880)이 화면 가운데에 뜨고, 작업 표시줄에 보인다.
- [ ] 사이드바는 보이지 않는다.
- [ ] 제목 표시줄 색이 앱 테마(라이트/다크)를 따른다.

## B. 전환
- [ ] 메인 창 왼쪽 아래 "사이드바로 전환" → 메인 창이 닫히고 사이드바가 터미널 옆(또는 화면 가장자리)에 붙는다. 작업 표시줄에서 사라진다.
- [ ] 사이드바 제목 줄의 창 아이콘 → 사이드바가 숨고 메인 창이 다시 열린다.
- [ ] 트레이 메뉴 "메인 창 열기" / "사이드바로 전환"이 같은 동작을 한다. 이때 앱이 멈추지 않는다(교착 확인).
- [ ] 앱을 종료했다가 다시 켜면 마지막으로 쓰던 쪽(메인/사이드바)으로 열린다.

## C. 단축키 · 트레이 · 재실행
- [ ] 메인 모드에서 Ctrl+Alt+Space: 메인 창이 앞에 있으면 최소화, 아니면 앞으로 나온다.
- [ ] 사이드바 모드에서 Ctrl+Alt+Space: 사이드바 보이기/숨기기 (Phase 1과 같음).
- [ ] 트레이 아이콘 왼쪽 클릭: 현재 모드의 창이 보인다.
- [ ] 이미 실행 중일 때 다시 실행: 현재 모드의 창이 보인다.
- [ ] 메인 창 X 버튼: 창이 닫히고 앱은 트레이에 남는다. 트레이에서 다시 열 수 있다.

## D. 화면
- [ ] 설정 → 테마 라이트/다크/시스템 전환이 즉시 반영되고, 사이드바로 전환해도 같은 테마다.
- [ ] 한글 글꼴(Pretendard)이 깨지지 않는다. 고해상도(125%, 150%)에서도 선명하다.
- [ ] 왼쪽 메뉴 접기/펼치기가 재실행 후에도 유지된다.

## E. 문서 작성기 (Phase 5, WebView2에서 확인)
- [ ] 왼쪽 블록을 캔버스로 끌어다 놓으면 블록이 생긴다. 블록 위 `+`를 누르면 가운데쯤에 생긴다.
- [ ] 블록 오른쪽 점을 CLAUDE.md 노드에 끌어 연결된다. 규칙 블록은 CLAUDE.md에 연결되지 않는다(규칙 출력에는 된다).
- [ ] CLAUDE.md 노드 안 목록의 손잡이(⋮⋮)를 끌어 순서를 바꾸면 미리보기 순서도 바뀐다.
- [ ] Ctrl+Z / Ctrl+Shift+Z로 되돌리기·다시 하기, Delete 키로 블록 삭제.
- [ ] "프로젝트에 쓰기" → 변경 내용 확인 → 쓰기. 기존 CLAUDE.md 내용은 그대로 있고 관리 구역만 추가/교체된다.
- [ ] 파일·폴더를 창에 끌어다 놓아도 앱 화면이 바뀌지 않는다.
- [ ] 사이드바가 작업 표시줄과 Alt+Tab에 나타나지 않는다(메인 ↔ 사이드바 전환 후에도).

## F. 브랜치 메모 (Phase 8a)
- [ ] 메모 탭(사이드바)과 메모 화면(메인)에 현재 프로젝트·브랜치가 보인다. git이 없거나 git 저장소가 아닌 폴더는 폴더 하나에 메모 하나.
- [ ] 메모를 쓰면 잠시 뒤 저장되고, 앱을 껐다 켜도 남아 있다.
- [ ] 할 일 추가(Enter)·완료 체크·글자 눌러 고치기·삭제·손잡이로 순서 바꾸기·"완료 항목 지우기".
- [ ] 터미널에서 `git switch 다른브랜치` 하면 몇 초 안에 그 브랜치 메모로 바뀐다. 목록에서 다른 브랜치를 고르면 "현재 브랜치로"로 돌아올 수 있다.
- [ ] 같은 저장소의 다른 worktree를 프로젝트로 골라도 같은 브랜치 메모가 보인다.
- [ ] 사이드바에서 고친 내용이 메인 창 메모 화면에도 반영된다(반대도).
- [ ] 리모트 없는 저장소에 메모를 쓴 뒤 `git remote add origin ...` 해도 메모가 그대로 남는다.
- [ ] `git rebase -i`로 멈춘 동안에도 리베이스 중인 브랜치 메모가 보인다.
- [ ] 메모를 치는 도중 브랜치를 바꿔도 글자가 사라지거나 다른 브랜치로 섞이지 않는다.
- [ ] git 실행 시 콘솔 창이 깜빡이지 않는다.

## G. 작업 탭 (Phase 7)
- [ ] 작업 탭(사이드바)과 작업 화면(메인)에 현재 브랜치, 원격 대비 ↑↓, 변경 파일, 브랜치, worktree가 보인다.
- [ ] git 저장소가 아닌 폴더는 단계별 설정 안내(GitHub 저장소 만들기 → 폴더 이동 → 이름 등록 → git init → 첫 커밋 → 올리기)가 나오고, 복사 버튼과 GitHub 아이디·저장소 이름 채우기가 된다. git init·첫 커밋·원격 연결을 할 때마다 남은 단계만 보인다. git이 없으면 설치 단계가 맨 앞에 나온다.
- [ ] 터미널에서 파일을 고치거나 `git switch` 하면 몇 초 안에 반영된다.
- [ ] 변경 파일을 누르면 diff가 열리고, 새 파일·바이너리·리베이스/병합 중 상태도 깨지지 않는다.
- [ ] + 로 새 브랜치를 만들고(기준 선택, "만든 뒤 전환"), 다른 브랜치로 "전환"할 수 있다. 전환하면 메모 탭도 그 브랜치로 바뀐다.
- [ ] 병합된 브랜치 삭제는 확인 1번, 병합 안 된 브랜치는 경고 2번 뒤에만 지워진다. 현재 브랜치·worktree에 열린 브랜치에는 삭제 버튼이 없다.
- [ ] + 로 worktree를 만들면 `.claude/worktrees/<이름>`에 브랜치 `worktree-<이름>`으로 생기고, 기본 worktree의 변경 목록에 `.claude/`가 나타나지 않는다.
- [ ] Claude Code가 만든 worktree에도 "Claude Code" 표시가 붙는다. "열기"로 그 worktree를 프로젝트로 열 수 있다.
- [ ] 변경이 남은 worktree 삭제는 경고 2번 뒤에만 되고, 기본·지금 열린 worktree는 지울 수 없다. 폴더를 직접 지운 worktree는 "정리"로 목록에서 빠진다.
- [ ] Windows 경로(`C:\...`)에서 "열림" 표시와 삭제가 맞게 동작한다.

## H. GitHub (Phase 9a, Client ID 설정 후)
- [ ] github.com 리모트가 있는 저장소의 작업 탭에 GitHub 섹션이 보인다(리모트가 없으면 안 보이고 설정 안내가 대신 나온다).
- [ ] "GitHub 로그인" → 코드가 크게 보이고, "코드 복사하고 GitHub 열기"로 브라우저에서 입력하면 몇 초 안에 로그인된다. 취소·거절·만료 시 안내가 나온다.
- [ ] 앱을 껐다 켜도 로그인이 유지된다(Windows 자격 증명 관리자에 `ai-management` 항목). 로그아웃하면 항목이 지워진다.
- [ ] 현재 브랜치의 PR(번호·제목·열림/초안/병합됨/닫힘)과 CI 결과(✓ ✗ ⏳ 개수)가 보이고, 누르면 브라우저에서 열린다.
- [ ] push 안 한 브랜치는 `git push -u origin <브랜치>` 안내가 나온다. push 후 "PR 만들기"(제목 기본값 = 마지막 커밋 메시지, 기준 브랜치, 초안)로 PR이 만들어지고 브라우저에서 열린다.
- [ ] 열린 PR·열린 이슈 목록을 펼쳐 볼 수 있고, 비공개 저장소도 보인다.

## I. 메모 동기화 (Phase 8b, `docs/sync-setup.md` 설정 후)
- [ ] 설정 › 동기화: GitHub 로그인 전에는 "작업 탭에서 GitHub에 로그인" 안내, 로그인 후 허용 전에는 "아직 허용되지 않은 계정" + 계정 ID(복사 가능)가 보인다.
- [ ] `allowed/{계정 ID}`를 만들고 "지금 동기화" → "마지막 동기화: 방금"이 되고, Firestore 데이터 탭 `users/{uid}/items`에 메모가 생긴다.
- [ ] 메모를 고치면 몇 초 뒤 Firestore에 반영되고, 메모 패널 저장소 이름 옆에 구름 아이콘이 보인다.
- [ ] 두 번째 기기(또는 다른 Windows 계정)에서 같은 GitHub로 로그인하면 1분 안(또는 창을 다시 누르면 바로) 같은 메모·할 일이 보인다. 한쪽에서 지운 할 일은 다른 쪽에서도 지워진다.
- [ ] 인터넷을 끊고 고친 메모는 연결되면 올라간다(그동안 메모 패널에 빨간 구름 + 오류 툴팁).
- [ ] 동기화 스위치를 끄면 더 올리거나 받지 않는다.
